# a-asnia.github.io

Публичный сайт-витрина на GitHub Pages. Отдаётся как есть, без сборки
на стороне GitHub (`.nojekyll`), с ветки `main`.

## Главное правило

**Репозиторий публичный. Всё, что сюда попадает, видно всем и навсегда.**

Git хранит историю: файл, удалённый следующим коммитом, остаётся доступен
в предыдущем. Поэтому приватные данные нельзя «закоммитить и потом убрать» —
их нельзя коммитить вообще.

Сюда попадает только собранная статика сайта: HTML, CSS, шрифты, картинки
и JS-бандлы генераторов.

## Чего здесь быть не должно

- ключи, токены, пароли, `.env`, сервис-аккаунты;
- личные e-mail, телефоны, адреса, документы;
- базы, дампы, бэкапы, экспорты;
- `.map`-файлы — они раскрывают полный исходный код и пути с локальной машины;
- рабочие заметки, черновики, внутренние ссылки;
- исходники приватных проектов — здесь только их сборка.

Ссылки на приватные репозитории (`bookmark-generator`, `clicker-generator`)
и упоминание того, что они существуют, — раскрывать можно. Это осознанное
решение, не утечка.

## Структура

| Путь | Что это |
|---|---|
| `index.html` | лендинг |
| `assets/site.css` | стили лендинга |
| `bookmark/`, `clicker/` | страницы-описания проектов |
| `bookmark-generator/`, `clicker-generator/` | сборки генераторов из приватных репозиториев |

Содержимое `bookmark-generator/` и `clicker-generator/` — артефакты сборки.
Их не правят здесь руками: изменения вносятся в исходном репозитории,
после чего сюда выкладывается свежая сборка.

## Перед коммитом

1. `git status` и `git diff --staged` — посмотреть глазами, что уходит.
   Особенно внимательно к новым файлам и к обновлённым бандлам.
2. Убедиться, что среди файлов нет `.map`, `.env`, дампов и архивов.
3. Проверить почту автора:

   ```
   git config user.email
   ```

   Должно быть `a-asnia@users.noreply.github.com`. Личная почта в коммите
   становится публичной и убирается только переписыванием истории.
   Задать один раз для этого репозитория:

   ```
   git config user.email a-asnia@users.noreply.github.com
   ```

## Если приватное всё-таки утекло

Не ограничиваться удаляющим коммитом — данные останутся в истории.
Нужно: отозвать скомпрометированный ключ или токен, затем переписать
историю (`git filter-repo`) и сделать force-push. Это ломает существующие
клоны и форки, поэтому такое решение принимает владелец репозитория.
